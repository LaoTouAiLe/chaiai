## 1. 范围

### 1.1 做什么（= 路线图 §v0.9 的六项，逐项落到本仓的具体缺口上）

1. **抽离执行适配器**：现在只有 `run_shell` 走进程登记表（§17.4）；`git`（`tools/git_tools.py:138`）、按需 RAG 的 `rg`（`rag/search.py:328`）、目录选择器（`directory_picker.py:159`）**各自直连 `subprocess.run`**，超时只能杀直接子进程、**管不了进程树**。把它们统一收进登记表，**工具 Schema 不变**。
2. **路径别名收口**：`_resolve` 已用 `Path.resolve()`（软链/junction 有实测），但 **UNC/网络路径、Windows 8.3 短名、结尾点/空格、`is_within` 的大小写比较**四项既无处理也无测试。
3. **资源上限**：环境变量、单次输出体积、超时**已有且有实测**；**CPU / 内存 / 磁盘总量 / 网络四类完全没有**。**2026-10-12 决定不做 CPU / 内存 / 进程数上限**（见 §3 T78 的撤销记录与 `docs/planning/FUTURE_WORK.md` 的 B-33 / B-34）；磁盘总量与网络出口继续"只声明边界"。
4. **数据库可靠性（起草时盘点）**：迁移框架与崩溃恢复分类已有；当时没有启动自检、备份/恢复流程。**T79 实证更正**：SQLite Saver 的 setup 已开启 WAL，原“未开 WAL”判断有误；本轮保留并补 WAL 实测。
5. **脱敏与审计**：投影出口与服务层错误路径**已脱敏且有实测**；但**工具原始输出会先进 Checkpoint、检索落盘文件（`tools/result_spill.py`）未见脱敏**——"敏感值只在本机库里"这条目前**没有负例**钉住；也没有独立审计日志。
6. **故障注入**：已有不少（模型失败、工具崩、取消竞态、流式半截尾、索引失败、损坏库）；**缺**：磁盘满（ENOSPC）、真实 `database is locked`、进程被 OS 杀、半写文件、Checkpoint 落盘中断。

### 1.2 这次不做（路线图的"不做" + 本仓口径）

- **不宣称"安全沙箱"或"完全隔离"**：没有实测过的隔离能力一律不写进 README、界面或文档。**这是本阶段的硬边界**。
- 不做多进程/容器化的产品形态改造（那要改 v0.6 §17.7 的停止条件）。
- 不做联网出口代理、不做带宽整形；网络只能"声明边界"（§5 待拍板④）。
- 不重写既有工具 Schema、不改事件与快照契约（执行方式变化不外泄到工具契约）。
- 不顺带补 v0.8 之前遗留的暂停项（真实模型效果 / T43 压力验收）。

### 1.3 盘点结论（三档，作为选任务的依据）

- **A 档（能越界执行 / 数据丢失的真缺口）**：① git / rg / 目录选择器绕过治理；② 无 CPU/内存/磁盘/网络限制；③ 无备份与 `quick_check`；④ 敏感值可能以原文落 SQLite / 落盘；⑤ UNC / 8.3 / 结尾点空格 / 边界大小写四项无处理无测试。
- **B 档（有能力但未验证）**：① 进程树终止只在**当前平台**分支被真跑（`test_process_guard.py:40` 按 `os.name` 二选一）；② rg/git 超时用假 runner；③ 目录选择器只伪造 `subprocess.run`；④ POSIX 持久凭据、非 Windows shell 适配器声明"未验证"；⑤ 故障注入面缺（见 1.1-6）。
- **C 档（已实现且有实测，本阶段只回归、不重做）**：`run_shell` 的进程树终止（`test_process_guard.py:110/130/160/201`）、路径边界（软链/junction/`~`/受保护目标）、环境变量收敛 + 输出截断 + 超时上限、迁移 + 崩溃恢复分类、投影与服务层脱敏、SSE 断开与流式半截尾收口。

### T77｜路径别名与边界收口（A⑤）

- **落点**：`security/path_guard.py` + 三处入口（工具层 / 审批层 / 执行层）。
- **验收**：对 UNC、8.3 短名、结尾点/空格、大小写四类**每类一条负例**（越界必须被拒），并在契约里写清**为什么选拒绝而不是归一**（或反之）。**Windows 专属项在非 Windows 上按"跳过并如实标注"处理**，不许假装跑过。
- **状态（2026-10-12，已完成，未提交）**：**先做了一轮只读实证**（四类在当前实现下的真实行为，修前修后各一次），据此**冻结 `ARCHITECTURE.md` §20.2**——四类各写死"归一 or 拒绝"。实证抓出**两处真缺陷**：
  - **① 尾点/空格 ⇒ 归一**（缺陷）：`resolve()` 只对**已存在**的目标展开，于是**干净目录里写 `".env "` 真的造出了 `.env`**，而 `is_sensitive_path(".env ")` 说"不敏感"——判定与执行看的是两个名字。修法：`_resolve` 解析之后**逐段**去尾点/空格（Windows 专属），校验与执行从此看同一个名字。
  - **④ 工作区外的远程路径 ⇒ 拒绝**（缺陷）：`\\localhost\C$\Windows\win.ini` 的 `protected_target_reason` 返回 `None`（它的父目录里没有本机的 `C:\Windows`）⇒ `external_paths.mode: allow` 下"系统关键目录不可审批"这条**硬约束被 UNC 别名绕过**。修法：工作区**外**的远程路径一律拒绝（任何档位、连**已授权**也不放行）；工作区自己就在共享上时不受影响（走"工作区内"那一支）。**这是能力收窄，已在契约里如实写明**（要编辑共享上的文件：把共享设为工作区，或改用本地路径）。
  - **③ 设备/扩展前缀（`\\?\`、`\\.\`）⇒ 拒绝**：实测 `\\?\…` 形态 `resolve()` **原样保留**（`..` 不被折叠），而 `\\.\C:\Windows\win.ini` 会被 `resolve()` **静默改写成普通路径** ⇒ 放行等于让"判定的路径"与"系统打开的路径"变成两条。新增 `_reject_aliased_device_path`，**边界入口与解析入口都先拒**。
  - **② 大小写 ⇒ 归一**（不新增规则）：实测**已经正确**（`.ENV` / `ID_RSA` 判敏感、`.GIT/config` 判受保护、`is_within` / `relative_to` 都不区分大小写）。本轮只补一处**未被证明**的比较：受保护判定的 `.git` 分段在 Windows 上 casefold——目标**尚不存在**时 `.GIT` 以前不算受保护（`resolve()` 取不到磁盘上的真实大小写）。
  - **⑤ 8.3 短名 ⇒ 跳过并如实标注**：本机卷**未启用** 8.3（`GetShortPathNameW` 返回长名）⇒ 别名行为**无法在本机证明**，因此不新增处理（既有 `resolve()` 对**存在**的目标会取长名），用例按**能力探测**跳过并写明原因。
  - 规则只写在 `security/path_guard.py` 一处，因为三处入口（工具层 / 审批层 `SecurityPolicy.resolve_*` / 执行层 `shell_guard` 的 cwd 与白名单）都经 `resolve_target` / `resolve_within_workspace` / `is_within`。
- **验收证据**：`tests/test_security.py` 新增 **6 条**（① 归一 + **写入方向的两条负例**（`.env ` / `credentials ` 必须被拒）+ 普通文件不受影响；② `.GIT` / `.GiT` 判受保护；③ **四条**设备前缀在"边界 + 解析"两个入口都被拒；④ 远程在 `deny` / `whitelist` / `allow` / **已授权** 四种策略下都被拒 + 工作区就是共享时的**正例**；⑤ 8.3 能力探测跳过；⑥ 回归：普通路径、`..` 逃逸、越界与全点分段行为不变）。定向 **64 passed / 2 skipped**；`ruff`、`mypy src`（129 文件）、`export_openapi.py --check` 全绿（**无 DTO/接口变化**——本轮只动路径判定）。
  - 过程中有一处**我自己的预期写错了、被用例当场抓住**：我以为"仅由点构成的分段"需要我保留，实际 `resolve()` 已经按 Windows 语义把它塌缩（`sub/.../a.txt` ⇒ `sub/a.txt`）。契约与测试都按实测改正，代码里那句只留作防御。

## 5. 待拍板（六项，都是会改变工作量的分叉）

1. **隔离方向**：本阶段是"**统一治理 + 明示边界 + 评估**"（我建议，照路线图"评估"的措辞），还是要**真上 OS 级隔离**（Windows 受限令牌 / Landlock / 容器）？后者会把 T78/T82 变成大工程，且很可能卡在"必须多进程"这条停止条件上。
2. **本机有没有 Linux/macOS 真机**：没有的话，POSIX 的进程终止、shell 适配器、持久凭据只能**继续声明"未验证"**——那 T77/T82 的验收范围要相应收窄。这是"只声明跑过的"的前提，必须先答。
3. **WAL 开不开**：开 WAL 影响并发与崩溃行为（对我们的单实例锁影响有限），但会改变备份与恢复的做法。建议**先做自检与备份，WAL 单列一条实测后再定**。
4. **网络出口**：本阶段只"声明边界"（不隔离），还是要做出口白名单？后者与"本地优先、不做联网代理"的既有口径冲突。
5. **审计日志**：要不要独立文件（谁在何时请求了什么动作、结果如何），还是只进现有结构化日志？独立文件会新增一份"看起来像真源"的东西，必须写清它不是。
6. **脱敏口径**：落盘/Checkpoint 允许保留原文（本机可信，加负例保证不进投影与日志），还是**写入前就脱敏**（更安全，但会改变模型看到的内容）？我倾向前者 + 负例，因为后者悄悄改变模型输入，属于"看不见的行为变化"。
