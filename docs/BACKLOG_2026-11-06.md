## 1. A 组：会影响用户（建议全做，约半天）

### A1 预览换文件串味 —— 旧文件的正文拼进新文件

- **位置**：`local-agent-web/frontend/src/features/panel/PreviewPane.tsx:65-73`（`loadMore` 的 `.then` 无条件 `setExtra`），`:49-50`（换文件的 `useEffect` 只清 state，不取消在途请求）
- **现状**：文件内搜不到 `AbortController`。切文件后旧响应回来，仍会 `setExtra((previous) => [...previous, next.text])`
- **影响**：A 文件的第 2 页被拼进 B 文件的 `body`，用户看到的是两份内容混排
- **修法**：请求带序号（`const seq = ++seqRef.current`，回调里 `if (seq !== seqRef.current) return`）或 `AbortController`；换文件时 `abort()`
- **验收**：手写一个前端用例——两次 `loadMore` 交错返回，断言 `body` 只含最后一次的文件内容。现有 `PreviewPane` 相关测试在 `frontend/src/features/panel/*.test.tsx`

### A2 隧道下手机 cookie 不带 `Secure`

- **位置**：`local-agent-web/src/local_agent/mobile/gateway.py:396`
- **现状**：`secure=request.url.scheme == "https"`。网关自己只听 http（TLS 由 tailscale / cloudflared 终结），所以走隧道时这里永远是 `False`
- **影响**：公网可达的 `funnel` 场景下，设备 cookie 不含 `Secure`，可被同网络的明文通道带出
- **修法**：读 `x-forwarded-proto`（tailscale serve 会带），或按通道配置声明 `tls: true` 时强制 `Secure`
- **验收**：`test_mobile_gateway.py` 加一条：带 `x-forwarded-proto: https` 的请求，响应 `Set-Cookie` 含 `Secure`

### A3 预览并发槽只护住了 Office

- **位置**：`local-agent-web/src/local_agent/application/document_preview.py:44`（acquire）/ `:76`（release）；PDF 直通在 `:24-27`，xlsx 解析在 `:82+`
- **现状**：`_slots = BoundedSemaphore(2)` 只包住 Office 转换那一段
- **影响**：并发请求 PDF / 大表格时不受限，32 MB × N 直接吃内存
- **修法**：把"读文件 + 解析"也纳入槽，或给 PDF/xlsx 单独限流
- **验收**：`test_visual_preview.py` 加一条并发 3 个 PDF 的用例，断言同时进入不超过 2 个

### A4 委派卡取消后无限轮询

- **位置**：`local-agent-web/frontend/src/features/tool/ToolCards.tsx:423-424`
- **现状**：`enabled: card.pending.length > 0` + 固定 `refetchInterval: 1500`
- **影响**：任务取消/结束后 `pending` 不清空，页面一直每 1.5 秒请求 `/api/delegation/live`
- **修法**：加"已结束就停"的判断（`pending.length > 0 && !finished`），或给 `refetchInterval` 传函数按状态返回 `false`
- **验收**：前端用例断言"取消后不再有新请求"

### A5 验证提醒会在最后一格额度触发

- **位置**：`local-agent-web/src/local_agent/graph/main_loop.py:61`
- **现状**：`if completed and verify_on_stop and not loop_limit_reached(state)`；`loop_limit_reached` 的定义是 `loop_count >= max`
- **影响**：`loop_count == max - 1` 时仍会提醒，最后一格额度被"去验证"用掉，下一轮直接 failed——正常收尾被判成失败
- **修法**：改成 `loop_count >= max - 1` 就不提醒
- **验收**：`test_verification_stop.py` 加边界用例（max-1 时不提醒）

### A6 `/delegation/live` 的注释与实现不一致

- **位置**：`local-agent-web/src/local_agent/api/routes.py:493`（docstring 写"只暴露**目录名与工具名**"）；`local-agent-web/src/local_agent/delegation_live.py:54` 实际有 `goal`（子任务提问原文，截断 200 字）
- **影响**：注释承诺的暴露范围小于实现，误导读代码的人；`goal` 里可能含用户输入
- **修法**：二选一——去掉 `goal`（前端只用目录名/工具名），或把注释改成事实
- **验收**：`test_delegation_live.py` 断言响应里不含 `goal`（若选去掉）

### A7 主服务没有日志落盘 + 前端没有 ErrorBoundary

- **现状**（刚核实）：全仓 `RotatingFileHandler|FileHandler(` 命中 **0**；`frontend/src` 里 `ErrorBoundary|componentDidCatch` 命中 **0**
- **影响**：uvicorn 输出到 stdout，双击 exe 的用户看不到任何日志——报障时你手里没东西；前端渲染异常直接白屏，用户连截图都截不到有用信息
- **修法**：
  - 后端：在装配层给 root logger 加 `RotatingFileHandler`，写 `data_root/logs/app.log`（滚动 5 MB × 3），`--diagnose` 里打印路径
  - 前端：`main.tsx` 外面套一个 `ErrorBoundary`，捕获后显示"重新加载 / 复制错误信息"
- **验收**：跑一次服务确认 `logs/app.log` 有内容；手动抛一个渲染错误确认看到兜底 UI 而不是白屏

## 6. 发版流程（照 0.2.0 / 0.3.0 的做法，别跳步）

1. 版本号三处一起改：`local-agent-web/pyproject.toml`、`local-agent-web/src/local_agent/__init__.py`、`local-agent-web/frontend/package.json`（`package-lock.json` 两处）+ `local-agent-web/uv.lock` + `api/app.py` 的 `API_VERSION`
2. `scripts/export_openapi.py` 重新导出 → `cd frontend; npm run generate:api; npm run check:api` → `scripts/check_release_contracts.py --write`
3. README（中英）的版本号与用例数字、`website/` 的页脚“适用版本”、`docs/DEVELOPING.md`
4. 一个 `chore(release): v0.3.1` 提交把上述收口
5. annotated tag：`git tag -a v0.3.1 -m "v0.3.1: <一句话>"`
6. 推送：`git -c "http.proxy=" -c "https.proxy=" -c http.version=HTTP/1.1 -c http.sslBackend=openssl push main master`，再 `... push main v0.3.1`
7. 盯两条流水线：
   - `release.yml` → 约 8-10 分钟，产物是 `chaiai-0.3.1-win64.zip` + `chaiai-setup-0.3.1.exe` + `SHA256SUMS.txt`
   - `pages.yml` → 部署官网
8. 用 `https://api.github.com/repos/LaoTouAiLe/chaiai/releases/latest` 核对三个产物的名字与大小

**tag 一旦推出去就占版本号**，错了要删 tag 重打（`git push main :refs/tags/vX.Y.Z` 后重建）。
