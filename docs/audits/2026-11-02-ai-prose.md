# AI 回复正文优化与验收

## 根因与改动目的

此前 `.root > :is(p, ...)` 将 Markdown 块的 margin 清零，选择器优先级高于相邻块的间距规则，导致预期的 16px 段落间距实际为 0。全局界面样式还将 ul/ol 设为 `list-style: none`，正文未恢复圆点和序号。这两处均已通过真实浏览器复现。

本轮以 DSH 的正文排版为依据，修复上述问题，并把时间和已完成的过程记录从主阅读流中收口。只改前端展示，不改变接口、消息调度或记录顺序。

## 展示规则

- 正文默认 14px/24px，字号设置仍生效；用户消息气泡继续使用其原有字号。
- 正文块之间保留 16px；h1–h3 通常上方 32px、下方 16px；文档首尾修剪多余留白。
- 无序列表恢复圆点、有序列表恢复数字，嵌套列表保留层级，任务列表使用复选框。
- 代码默认 12px/20px，长行只在代码框中横向滚动。表格在自身区域横向滚动。代码复制沿用原逻辑，未新增高亮依赖。
- 每轮只显示最后一条助手消息的时间；统计与复制/引用操作放在轮尾。
- 只有已完成、全部工具成功、存在工具之后的最终回答，且没有错误/记忆/压缩记录、没有流式输出、没有主动展开工具时，才默认收起前面的过程。展开后仍按原消息顺序显示。
- 当前运行、等待审批、等待回答、失败、不确定、待执行的记录，以及用户主动展开的工具，不会被该过程折叠隐藏。
- 思考仍可独立展开/收起，展开后使用紧凑 Markdown 并跟随会话整体滚动；原始 HTML 不执行、远程图片不自动请求的规则保留。

## 验证结果

- 生产构建、TypeScript 检查通过。
- 完整前端单测：73 个文件、721 项通过。
- 浏览器验收：20 项通过，覆盖 1440×900、1280×800、768×900、390×844。原有 48 组页面/主题组合仍通过。
- 新增正文用例检查浅深色的实际计算样式：14px/24px、16px 段落间隔、32px/16px 标题间距、disc/decimal 列表、12px/20px 代码、文档首尾间距；验证大/小字号偏好、代码内部滚动、页面无横向溢出、思考区域不再局部滚动。
- 新增过程用例检查最终回答保持可见、工具过程可展开/收起、每轮只有一个回复时间。
- 修改的 TSX 与浏览器用例 ESLint：0 错误、0 警告。`git diff --check` 通过。
- 本地预览 `http://127.0.0.1:5173/api/health` 返回 200。

用相同文本、相同 736px 正文列宽再次对照 DSH 的原始样式：段落、h2、ul/ol 的字号、行高、margin 与列表标记均与参考一致。此对照将 DSH CSS 应用到同一份生成的 HTML，并非启动完整 DSH 应用。
