# PowerShell 7 受控终端初始化修复

## 根因与修复

受控终端已经创建进程并连接 WebSocket，但 IPC 兼容组件把 CLR 管理的 IL-only 程序集当普通 native DLL 扫描。日志显示扫描到 `_CorDllMain` 后在锁内触发加载重入，pwsh 停在提示符之前。cmd 和系统 Windows PowerShell 的对照通过；关闭用户 profile、禁用 PSReadLine、改变 ConPTY 标准句柄均未解决。仅在诊断进程中取消 IPC 注入可恢复，但没有把它作为产品修复。

最终修改 `local-agent-web/src/local_agent/native/windows/ipc_compat.c`：读取 CLR 目录、检查头部边界，跳过 IL-only 映像；CoreCLR、native 和 mixed-mode 模块仍执行原有拦截。原始导入表存在时按它的零终止项结束扫描，不再只依赖当前 IAT 内容。没有修改限制令牌、写授权、Job、注入传播或产品 shell 选择，也没有采用实验中的 TLS/锁改动。

`ipc_compat.c` 和 `ipc_common.c` 的 WinAPI 函数指针转换经 `void*` 转换，以通过本机 Zig 0.15.2 的严格编译检查。原记录为 Zig 0.17.0，但本机无该编译器且该版本没有 Windows wheel；隔离安装了 0.15.2，未改变 Python/前端项目依赖。x64/x86 DLL、loader 和 manifest 均已重建，源码与分发哈希检查通过。
