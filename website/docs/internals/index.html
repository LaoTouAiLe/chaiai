技术实现说明

讲清「为什么这么实现」，而不只是「这里有个函数」。每章一页，结论要落到具体代码路径， 没有实测过的推断单独标注，不混进结论里。

写作口径：正文里出现的行为结论必须能指到 文件:行号； 涉及「必须人工批准」「默认关闭」这类承诺时，同时给出对应的服务端判据，而不是只引前端文案。 未验证的部分写「未验证」并说明验证方法。
  1. 01 架构总览：两层界面与一支执行链 React 界面 / FastAPI 唯一入口 / LangGraph 按轮推进 / 本机存储；界面为什么只发请求而不碰文件。 已可阅读
  2. 02 一轮请求的生命周期 提交 → 预检 → 组装上下文 → 模型与工具循环 → 投影到页面；中断、恢复与「结果不确定」的边界。 已可阅读
  3. 03 工具层与安全判据 工具注册与能力开关、审批判定落在哪一层、破坏性命令名单为什么只能追加、哪些工具可以并行。 已可阅读
  4. 04 写侧沙箱与权限判定 三档语义、Windows 受限令牌、工作区与临时目录边界、受保护目标与敏感文件；授权记录与判定顺序。 已可阅读
  5. 05 记忆与上下文压缩 Checkpoint、长期事实、中期向量记忆三层各存什么；压缩阈值、保留策略，以及为什么压缩不改写原始记录。 已可阅读
  6. 06 浏览器与持久进程 独立浏览器宿主怎么启动、登录状态与个人浏览器的隔离；持久进程的输入输出、停止条件与运行目录清理。 已可阅读
  7. 07 前端数据流与轮次展示 草稿、会话与轨迹分别放在哪；流式与快照怎么合并；投影 DTO 为什么只回引用、不回原始字节。 已可阅读
  8. 08 测试与验收方式 假模型与夹具、确定性评测脚本、真实模型验收的成本纪律；哪些结论只能由真机或真实端点证明。 已可阅读
