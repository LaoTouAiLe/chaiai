看屏幕与操作屏幕

先让模型"看见"当前窗口，再允许它在同一个窗口上点击与输入；两件事分开开关、分开审批。

1 只截前台窗口

整屏会把任务栏、通知与无关窗口一起拍进来，隐私面随窗口数量增长。所以只取当前前台窗口的矩形 （screen_capture.py:97 的 _rect_and_title）：取不到、窗口没有可见区域， 一律明确失败，不退回整屏。

  • 不落工作区。截图走系统临时目录，按条数滚动淘汰（CACHE_LIMIT=20， screen_capture.py:45）。
  • 与看图分开。image_read 的闸门是"这条连接能不能收图"， 截屏除此之外还有平台闸门与隐私面，所以单独登记成 screen_read。

2 控件树与编号

截图能"看见"，但拿不到"这个按钮叫什么、能不能点"。read_ui 把前台窗口的控件树压成一段 有界文本，可交互控件带编号，供 click_element 引用。

编号只对最近一次读数、同一个窗口有效。点击前会比对当前前台窗口， 窗口变了就要求重新读（tools/screen_tools.py:294-301），不会用旧坐标点到别的程序上。

3 动作只有五个

工具作用能力开关
screenshot截当前前台窗口给模型看screen_read
read_ui读控件树，给出编号screen_read
click_screen / click_element按坐标或编号单击screen_control
type_text / press_keys输入文本、按组合键screen_control
focus_window把某个窗口切到前台screen_control，且每次都要批

不做拖拽、滚轮、右键菜单与多段宏。每个动作都要过审批、都要能在失败时收尾，动作越多收尾面越大。

4 授权粒度：本轮一次

  • 第一次动作弹一次卡，之后本轮内同类动作不再逐个询问（security/policy.py:773-800）。 策略实例随轮次重建，所以这不是"记住批准"。
  • 换窗口立即撤销。授权对象是"那个窗口"，不是"这台机器" （policy.py:806-812）；下一次动作重新请求批准，卡片上是新窗口的标题。
  • 每轮有上限。最多 20 个动作（screen_input.py:34），数到顶就拒绝， 而不是无限连续点击。
  • 切前台单独批。focus_window 改的是用户此刻的焦点，可能正打着字、开着菜单， 所以不并进上面那条"本轮一次"。

5 默认值与平台

  • screen_read 与 screen_control 出厂默认关闭，并且 不进任何内置档位——打开是用户的显式决定，不是档位的副产品。
  • screen_control 还要求当前处于工作区可写档位：它会改动别的程序的状态。
  • 只在 Windows 可用：截图走 Win32 与 Pillow，控件树与输入走 uiautomation + comtypes；非 Windows 上 available() 直接返回不可用，不假装支持。
