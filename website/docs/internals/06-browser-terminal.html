浏览器与持久进程

这两样都是"活过一轮请求"的资源。共同的三条约束：独立宿主、独立登录态、必须能被显式停掉。

1 四种资源，四套生命周期

资源谁发起上限与寿命怎么停
模型浏览器 模型的 browser 工具 同一对话一个，跨轮复用（tools/browser_tools.py:264-267） close 动作、取消、权限变化、进程退出
面板浏览器 右栏里你手动打开的标签 最多 6 个；无人连接 30 分钟后回收（application/browsers.py:21-22、:330-331） 关标签、空闲回收、服务关闭
转后台命令 run_shell 被你点"转后台" 不设寿命，跑完为止（tools/shell_tools.py:202-227） stop_command、取消
交互终端 终端面板，需批准后启动（application/terminals.py:1） 每个终端输出 2 MB、单次输入 16 KB；30 分钟无输入结束（:26-28） 手动结束、空闲超时、服务关闭

四种资源都登记在同一张进程内资源表里，键是"工作区 + 会话作用域"，并且带权限指纹： 权限变化后旧资源会被直接关闭并拒绝复用（tools/runtime_sessions.py:63-73）。 表不落盘，服务重启后一律从头启动（tools/runtime_sessions.py:43-44）。

2 浏览器宿主怎么起

不下载、不安装，只探测本机已有的 Chromium 系浏览器：先查 PATH 里的 msedge / chrome / chromium，再查几个常见安装目录； 一个都没有就给出"装 Edge / Chrome / Chromium 后重新打开能力面板"的可执行提示 （tools/browser_tools.py:35-61）。

启动参数是固定的，不接受任意可执行文件、任意 flags 或宿主 JS（tools/browser_tools.py:97-111）：

msedge.exe
  --user-data-dir=<本次会话目录>/profile
  --remote-debugging-address=127.0.0.1   # 只绑回环
  --remote-debugging-port=0              # 端口由系统分配，启动后从 DevToolsActivePort 读
  --no-first-run --no-default-browser-check
  --disable-background-networking --disable-breakpad --disable-crash-reporter
  --window-size=1440,900
  [--headless=new]                       # 只有面板浏览器加这一段
  about:blank
  • 就绪判定不是"睡一会儿"：等 profile 目录里出现 DevToolsActivePort，读端口与路径再连 CDP；超时、进程提前退出、本轮被取消都会关掉进程并报错（tools/browser_tools.py:130-153）。
  • 环境变量被重定向：TEMP / TMP / TMPDIR / APPDATA / LOCALAPPDATA 全部指向本次会话目录，浏览器不往你的用户目录里写缓存（tools/browser_tools.py:106-109）。
  • 下载默认禁止：连接建立后第一条 CDP 命令就是 Browser.setDownloadBehavior {"behavior":"deny"}，要下载得显式给已授权的目录（tools/browser_tools.py:148、:271-272）。
  • 只认网页协议：http / https / about:blank，URL 里带明文账号密码直接拒绝；本地 HTML 要先起一个本地 HTTP 服务（tools/browser_tools.py:64-71）。

3 登录态为什么不会串

因为每启动一次都是全新的 profile：--user-data-dir 指向 .agent-runtime/<摘要>/session/browser-<uuid>/profile， 与你个人浏览器的配置目录毫无关系（tools/browser_tools.py:87-98）。 这不是"顺手加的隔离"，而是这个能力的定义：用独立登录状态（tools/browser_tools.py:273）。

代价要说清：它不共享你的登录态。需要登录的站点得在这个宿主里登一次， 而且那份 profile 随会话目录走——会话结束、目录被清理，登录状态也就没了。

面板浏览器还有一条"谁在操作"的规则：同一个浏览器同一时刻只能有一个控制器， 另一个页面要接管必须显式 take_over，否则报"已在另一页面连接" （application/browsers.py:294-306）。

4 画面是怎么到页面上的

  • 一个线程串行处理 CDP：所有命令进一个上限 128 的队列，按序执行——CDP 不是线程安全的，并发调只会互相踩（application/browsers.py:1、:35）。
  • 有人看才推：只有连上控制器时才 Page.startScreencast，断开就停（application/browsers.py:188-196）。
  • 只保留最新一帧：画面是"当前状态"而不是录像，跟不上就丢中间帧（application/browsers.py:1）。
  • 面板里的浏览器没有真实窗口：它以 visible=False 启动，等于 headless，你看到的画面是抓帧（application/browsers.py:47）；模型工具的 visible 默认 true，会弹一个真实窗口（tools/browser_tools.py:258）。

5 持久进程的输入输出

"持久"在代码里是两件事，别混：转后台的命令与交互终端。 前者是 run_shell 跑到一半被你转到后台，结果里 status 变 running 并带 command_id，之后用 read_command 看增量、 stop_command 结束（tools/shell_tools.py:358-360）。

转后台不是终止：进程本身与已读输出一起被交给接管回调，返回值只标记 detached=True（security/process_guard.py:259-262、:288-312）。 措辞也有意留了口子——退出码未知、进程仍在跑，所以不能说"完成"（tools/shell_tools.py:251-256）。

交互终端的形状更简单：一条命令一个会话目录，两个输出流各自落文件，读取按下标增量：

  • 目录：runtime_directory(policy) / <uuid>/，里面是 stdout.txt 与 stderr.txt（tools/terminal_tools.py:44-46、:61-75）。
  • 读取按 offsets 推进，所以"再读一次"不会重复吐出旧内容（tools/terminal_tools.py:46）。
  • 输入走队列，容量 16；stdin 保持打开，所以能连续交互（application/terminals.py:49）。

6 进程是怎么被停掉的

subprocess.run(timeout=...) 只杀直接子进程，而实际干活的是 Shell 适配器的子进程： 杀父进程之后命令还在后台跑（security/process_guard.py:5-8）。所以这里全部用 Popen 并显式管理进程树：

  • Windows：taskkill /F /T /PID 递归终止整棵树（security/process_guard.py:445-460）。
  • POSIX：按进程组发 SIGTERM，宽限期后 SIGKILL（security/process_guard.py:475-492）。
  • 终止手段与系统返回一律写进说明，不伪造"已停止"（security/process_guard.py:23-24）。
  • 唯一出口：源码里所有子进程都从这一层出去，包括 git、rg 与目录选择器——否则"取消"够不着它们（security/process_guard.py:18-21）。

自动停止的条件分散在各处，但都指向同一条终止路径：

  • 用户取消或手动结束：终端 stop、浏览器 close、命令 stop_command。
  • 空闲：终端 30 分钟无输入结束（application/terminals.py:28、:302-303）；面板浏览器 30 分钟无连接回收（application/browsers.py:319-338）。
  • 权限变化：旧资源带不上新权限，直接关闭并要求重启（tools/runtime_sessions.py:69-73）。
  • 服务退出：close_all 逐个作用域收尾，并注册在 atexit 上（tools/runtime_sessions.py:108-117）。

7 运行目录与清理

所有运行产物都落在工作区内的 .agent-runtime/<会话摘要>/session/； 建目录这一步本身也要走 resolve_writable_path，所以它同样受档位、授权与受保护目标约束， 并在 .agent-runtime/ 下写一份 .gitignore（内容为 *），避免被误提交 （tools/runtime_sessions.py:29-40）。

  • 浏览器目录在 close 时删除；删不掉只记一条告警，不阻塞关闭（application/browsers.py:230-239）。
  • 截图不指定路径时默认落 .agent-runtime/screenshots/，且先检查可写再截图，不留"先做再拒"（tools/browser_tools.py:371-373）。
  • 代码执行用的临时脚本目录在结束时删除（tools/shell_tools.py:466）。

8 这一层不是容器

  • 浏览器是真进程，只是用了独立 profile 与回环调试端口；它跑在你的账户下，能访问的东西和你一样多。网页内容一律当数据，不是指令（tools/browser_tools.py:273）。
  • 读侧不隔离，这与写侧沙箱的边界一致（见第 4 章）：能限制的是"写到哪"和"起什么"，不是"读到什么"。
  • 资源表只在进程内，服务重启后终端与浏览器都要重新打开——这是单进程设计的直接结果（tools/runtime_sessions.py:43-44）。
未验证的部分：抓帧的实际流畅度、take_over 的交互手感、超时回收在长任务里的表现， 本轮只读源码，没有起服务实测；也没有在本机打开真实浏览器观察登录态是否确实独立。 验证方法：在面板浏览器里登录一个站点，关闭后重新打开，确认需要重新登录； 另开一个终端跑 ping -t 127.0.0.1，什么都不输入，等 30 分钟看它是否被结束。
