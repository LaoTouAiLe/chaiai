常见问题与自检

先判断是哪一类：页面没起来、模型连不上、写入被拒，还是任务停在半路。每一类都给可执行的下一步。

打开页面是空白，或提示「前端产物不存在」

前端还没构建。在 frontend/ 执行 npm ci 与 npm run build， 然后刷新；开发态可以改用 npm run dev（访问 5173，/api 自动代理到 8000）。 提示「构建目录里没有 index.html」时同理，重新构建即可。

启动就退出，或不知道哪里配错了

uv run python -m local_agent.api --diagnose

它输出 {"ok": …, "checks": [...]}，逐项给出配置、前端产物、三个数据库、向量库依赖、 git / rg、模型配置与作用域检查；ok 为假时进程退出码是 1。 它不启动服务、不读密钥，也不证明沙箱或真实回答质量。

想换端口改 config.yaml 的 web.port；想换监听地址必须同时打开 web.allow_non_loopback，否则启动校验会直接拒绝——这是防止「改一行就暴露到公网」的保护。

连不上模型（401 / 403 / 429 / 超时）

  • 先点连接卡上的「测试连接」，看分项结论落在聊天、工具还是流式这一项。
  • 401 / 403 多是密钥或鉴权方式不对；429 是限流；超时看设置里的超时与重试次数。
  • 端点与模型 ID 要按供应商文档逐字核对；报错原文由供应商决定，这里不代为解释。

重启后要重新填密钥

说明这次启动没有可用的设置库，密钥只存在本次进程里（页面会显示「仅本次进程内 · 重启后需重新录入」）。 恢复设置库路径后重新填写一次，之后就会持久保存——仍然只写入、不回读。

写入被拒绝

  • 目标是工作区外：需要在「设置 → 权限 → 外部可写目录」里加授权，且当前档位不是「只读」。
  • 用了相对路径或 ~：外部路径必须写绝对路径。
  • 目标是根目录、用户主目录、系统目录或 Git 元数据：这些不能被授权写入。
  • Linux / macOS 上没有 OS 级写边界，拒绝来自服务端判据而不是系统沙箱。

任务一直停在运行中

点「停止生成」。停止会中断本轮，但不撤销已经发生的工具调用；停止请求失败时按提示刷新后重试。 同一会话的第二个提交不会排队，会直接被拒绝，所以不要靠重复发送来「催」它。

结果不确定

按第 4 章的核对流程收尾：刷新 → 查看本轮记录与文件 / 命令结果 → 勾选确认 → 「结束中断任务」。 在核对之前，不要重复执行可能带副作用的命令。

数据库自检、备份与恢复

先停止服务，再在 local-agent-web/ 下执行（路径按实际配置修改，输出用新名字）：

.venv/Scripts/python.exe scripts/database_maintenance.py check --database data/checkpoints.sqlite
.venv/Scripts/python.exe scripts/database_maintenance.py backup --database data/checkpoints.sqlite --output backups/checkpoints-20261019.sqlite
.venv/Scripts/python.exe scripts/database_maintenance.py restore --backup backups/checkpoints-20261019.sqlite --output data/checkpoints-restored.sqlite
.venv/Scripts/python.exe scripts/database_maintenance.py check --database data/checkpoints-restored.sqlite

确认恢复副本自检通过后，把 config.yaml 的 memory.short_term.path 指向恢复出来的文件，再按原命令启动。原库与备份都保留，不直接覆盖；恢复出的未结束任务仍需人工核对，不会自动重跑。

不要删库：服务启动时会对聊天库做 quick_check，失败就停止并提示保留原库与 -wal / -shm。运行中的主 .sqlite 不能只复制一份——已提交内容可能还在 WAL 里， 请用上面的备份命令。

界面太小 / 动画晃眼

「设置 → 通用与外观」可以改主题（浅色 / 深色 / 跟随系统）、文字大小（小 / 标准 / 大）与界面动画； 关掉动画后，页面还会尊重系统的「减少动态效果」设置。
