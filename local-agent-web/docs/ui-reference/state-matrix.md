## 4. 相邻差异（避免误用参考）

1. **提问卡（17）不是审批卡**：17 是"向用户提问"，18 才是"请求授权"，两者视觉相似但语义与按钮不同。
   本项目 v0.4 只实现审批接管（T32），提问卡不在范围。
2. **轨迹有两个入口**：页签「轨迹」是表格态（20），工具卡上的 `Inspect` 打开时间线 + 检查器（21）。
   本项目 v0.4 需要的是"计划 / 工具 / 证据可读"，可选择其一，不必两个都做。
3. **推理块（16）与 §6.7 冲突**：参考会把 reasoning 原文折叠展示，本项目 v0.4 明确**不得展示**
   `reasoning_content`。16 只用于参考"可折叠块的交互与视觉"，内容层面不照做。
4. **网页工具（13、14）** 在 v0.5 才实现，v0.4 不得伪造联网过程。
5. **参考的历史会话永远处于"运行中"**：内置世界里 `fx-alpha` 的 `running=true` 不复位，因此
   `03-conversation` 也带着 `Deep diving…` 阶段指示与"等待回答/进行中"的侧栏状态。对照时只看会话壳、
   消息流与统计行的排版，不要把该阶段指示当成"普通对话的应有状态"。
6. **侧栏状态点与运行时长是实时值**：截图里的"1分钟/2分钟/23秒"等相对时间随采集时刻变化，属于噪声，
   对照时不作为设计依据。
7. **参考的停止按钮（06）本项目不复制**：v0.4 不公开 `cancel_task()`，架构禁止渲染没有后端语义的停止按钮。
   本项目的运行中状态是"阶段态 + 可继续写草稿 + 暂时禁用发送并说明任务进行中"。

## 5. 状态覆盖之外需要补充的原型

参考页面**没有**、但 v0.4 要求或本项目特有，需要由本项目自行出原型，沿用同一套设计语言验收。
其中前两项是 **T26 的早期视觉检查点**——必须在页面全部写完之前先出原型并取得用户确认。

| 待补原型 | 内容与约束 | 归属 / 时点 |
|---|---|---|
| **完整文件 diff**（早期检查点） | 自有 fixture，**至少双 hunk**，含增删行与长行；两个固定视口截图。参考的 07 只用于卡片外观 | T26，早期；确认前不得称"已高保真还原"，也不是 T32 的既成基线 |
| **供应商错误态**（早期检查点） | 鉴权失败 / 限流 / 超时或重试耗尽三种，确定性 fixture；必须有可执行提示，不得露出原始响应或密钥；不接真实 provider、不消耗 API Key | T26，早期；真实行为留到模型连接与错误链路任务验证 |
